cosmodol.routing¶

Route an operation through a wrapped store’s own __setitem__/__delitem__.

The functions in cosmodol.ops need Cosmos semantics a mapping write does not have (a conditional replace, a transactional batch, a cascading delete, a parameterised create). Calling the leaf directly skips every wrapping layer’s own write logic: write guards, write-through caches, preset= hooks, scope filters on new keys (i2mint/cosmodol#3). Instead, an operation redirects the leaf: it installs a one-shot handler for one leaf method, then performs the plain mapping write (store[k] = v / del store[k]) on the caller’s outer store. Every layer runs exactly as for that write; when the call reaches the leaf, the leaf hands its (fully mapped) arguments to the handler instead of doing its usual upsert or delete.

>>> class Leaf(dict):
...     def __setitem__(self, k, v):
...         if (handler := claim(self, "__setitem__", k)) is not None:
...             return handler(k, v)
...         super().__setitem__(k, v)
>>> leaf = Leaf()
>>> with redirect(leaf, "__setitem__", "a", lambda k, v: f"handled {k}={v}") as r:
...     leaf["a"] = 1
>>> r.result, dict(leaf)
('handled a=1', {})

The redirect is pinned to the leaf key the operation computed (dol.inner_most_key), so a layer that writes some other key first (an index, an audit record) cannot have the operation’s semantics applied to it: that write is refused instead.

The redirect is held in a ContextVar, so it is invisible to other threads and tasks, and it only applies to the leaf object it names. The flip side: a layer that performs the write in another thread, or later (a write-behind buffer), escapes it, and that write happens as the leaf’s ordinary upsert or delete.
