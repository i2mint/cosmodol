cosmodol.base¶

Close-to-metal CRUD facade for Cosmos DB.

Functional layer over ContainerProxy. Each function takes the container plus normalized args and returns (value, ResponseHeaders) so callers can observe RU charges and ETags. The Mapping-shaped stores in cosmodol.stores route all their work through these.

See misc/docs/architecture.md Layer A.

Subset of Cosmos response headers we surface for observability.

request_charge¶

RU consumed by the operation. None when the emulator (which does not populate this header) was the backend.

etag¶

ETag of the (created / read / replaced) item, when applicable.

Transactional batch within one logical partition.

Parameters:

  • operations (list[tuple]) – List of (op_name, args_tuple, kwargs_dict) triples. Cosmos op names: "create", "upsert", "replace", "patch", "read", "delete". ≤ 100 ops, ≤ 1.2 MB total.

cosmodol.base.point_contains(container, id, partition_key)[source]¶

Existence check via point read. True/False. Never raises KeyError.

Cheaper than a SELECT VALUE COUNT(1) query — ~1 RU vs ≥ 2.3 RU.

Insert-or-replace an item. id and the partition-key value are extracted from body.
